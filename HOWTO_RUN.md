# Как запустить MyMoney (после Этапа 4)

Этот документ — практическое руководство: что установить на ПК, как поднять
бэкенд, как собрать и запустить приложение на Android-смартфоне.

> **Что уже работает.**
> - Этапы 1–3 — офлайновая работа приложения (счета, категории, операции,
>   бюджеты, цели, аналитика, PDF).
> - **Этап 4** — семейные приглашения, облачная синхронизация push/pull.
>   Для этого нужен запущенный бэкенд.
> - Приложение по-прежнему работает без сети (Offline First): всё, что нужно
>   для базового ведения бюджета, доступно и без входа в учётную запись.

---

## 1. Что установить на ПК (Windows 11)

| Инструмент | Версия | Для чего |
|---|---|---|
| **Docker Desktop** | последняя | Локальный PostgreSQL для бэкенда |
| **JDK 17+** (Temurin/Corretto) | 17 или новее | Компиляция и запуск Ktor-сервера |
| **Flutter SDK** | 3.24+ | Сборка мобильного приложения |
| **Android Studio** | последняя | Android SDK, эмулятор, платформенные инструменты |
| **Git** | любая | Уже установлен, репозиторий локальный |

Проверка после установки (PowerShell):

```powershell
docker --version
java -version                 
flutter --version
flutter doctor -v             # покажет чего не хватает
```

`flutter doctor` может ругаться на «Android toolchain — license status
unknown». Принять лицензии:

```powershell
flutter doctor --android-licenses
```

## 2. Запуск бэкенда на ПК (по желанию)

### 2.1. Поднять Postgres в Docker

Из корня проекта (`C:\Users\nika2\OneDrive\Desktop\MyMoney`):

```powershell
# Скопировать пример env — переменные будут прочитаны docker-compose и сервером
Copy-Item .env.example .env

# Поднять Postgres в фоне
docker compose up -d postgres

# Проверить, что контейнер здоров
docker compose ps
```

Postgres поднимется на `localhost:5432`, база `mymoney`, пользователь
`mymoney`, пароль `mymoney_dev_password` (значения из `.env`).

### 2.2. Собрать и запустить Ktor-сервер

```powershell
cd backend
.\gradlew.bat run
```

Первый запуск скачает Gradle wrapper и все зависимости — займёт 3–5 минут.
Далее сервер стартует за секунды.

Если увидите в логах:
```
Application started in ... seconds.
Responding at http://0.0.0.0:8080
```
— всё ок. При старте Flyway применяет `V1__initial_schema.sql`
автоматически (создаст все таблицы).

### 2.3. Проверить, что бэкенд отвечает

Новое окно PowerShell:

```powershell
# Health-check
curl.exe http://localhost:8080/healthz
# Ожидаемый ответ: {"status":"ok","db":"up"}

# Регистрация пользователя
curl.exe -X POST http://localhost:8080/v1/auth/register `
  -H "Content-Type: application/json" `
  -d '{\"email\":\"me@example.com\",\"password\":\"password123\"}'
# Вернёт accessToken, refreshToken, userId, familyId

# Список системных категорий (используйте accessToken из шага выше)
$TOKEN = "<вставь accessToken>"
curl.exe http://localhost:8080/v1/categories -H "Authorization: Bearer $TOKEN"
```

### 2.4. Прогнать автотесты бэкенда

Docker должен быть запущен — Testcontainers поднимет отдельный Postgres.

```powershell
cd backend
.\gradlew.bat test
```

Все тесты — юнит + интеграция для auth, accounts, categories, transactions
— пройдут ~30–60 секунд.

Остановить сервер: `Ctrl+C` в окне, где запущен Gradle.
Остановить Postgres: `docker compose down` (данные сохранятся в volume).

## 3. Сборка мобильного приложения

### 3.1. Установить зависимости и сгенерировать код

```powershell
cd mobile
flutter pub get
# Isar-энтити и *_entity.g.dart генерируются build_runner:
dart run build_runner build --delete-conflicting-outputs
```

Второй шаг создаст файлы `*_entity.g.dart` — без них проект не соберётся.

### 3.2. Что запускать

Есть три варианта:

**A. Windows-приложение на самом ПК** (быстрая проверка UI без телефона):

```powershell
flutter run -d windows
```

**B. Android-эмулятор** (Android Studio → Device Manager → Play):
Затем в PowerShell:
```powershell
flutter devices                     # проверить, что эмулятор виден
flutter run                          # запустится на эмуляторе
```

**C. Реальный Android-смартфон** — см. § 4 ниже.

## 4. Запуск и тест на реальном Android-смартфоне

### 4.1. Подготовить телефон

1. **Включить режим разработчика:**
   Настройки → О телефоне → нажать «Номер сборки» 7 раз.
2. **Включить USB-debugging:**
   Настройки → Для разработчиков → Отладка по USB.
3. **Подключить телефон USB-кабелем** к ПК.
4. **На телефоне** — разрешить отладку с этого ПК (появится диалог при
   первом подключении, поставить галочку «Всегда»).

### 4.2. Проверить, что ПК видит телефон

```powershell
flutter devices
```

В списке должна появиться модель вашего телефона. Если её нет:
- переустановить драйверы через Android Studio → SDK Manager → SDK Tools →
  Google USB Driver;
- сменить USB-кабель;
- переключить в настройках телефона USB-режим на «Передача файлов».

### 4.3. Запустить приложение на телефоне

Из папки `mobile/`:

```powershell
flutter run                          # автоматически выберет подключенный
                                     # телефон если он единственный
# или явно указать:
flutter run -d <device-id-из-flutter-devices>
```

Первая сборка займёт 3–7 минут (компиляция Isar C++ библиотек под ARM).
Приложение установится на телефон и запустится автоматически.

### 4.4. Собрать отдельный APK и установить вручную (без USB)

```powershell
flutter build apk --release
```

Готовый APK: `mobile/build/app/outputs/flutter-apk/app-release.apk`.
Скиньте его на телефон (Google Drive, Telegram, USB), откройте с
телефона — Android предложит установить (нужно разрешить «установку из
неизвестных источников»).

## 5. Что тестировать вручную на смартфоне

Приложение работает **полностью офлайн** и **не хранит никаких аккаунтов**.
Каждая установка — отдельная «локальная семья». Поэтому сценарии простые.

### Приёмочный сценарий Этапа 1 (по § 24 Bible)

1. **Первый запуск.**
   Приложение открывается, показывает пустой экран «Главная», сумма
   баланса `0,00 ₽`.
   Проверка: при первом старте автоматически создались:
   - счёт «Наличные»;
   - все системные категории (проверить на вкладке «Операции» → добавить
     операцию — категории появятся списком).

2. **Добавить расход за ≤ 3 шага (ключевой DoD Этапа 1).**
   Нажать `+ Операция` внизу справа.
   - Шаг 1: тап по чипу счёта («Наличные»).
   - Шаг 2: тап по категории «Продукты».
   - Шаг 3: ввести сумму, например `500`, нажать «Сохранить».

   Приложение вернётся на предыдущий экран, операция появится в разделе
   «Последние операции» и в списке «Операции». Баланс на главной
   уменьшится на 500 ₽.

3. **Добавить доход.**
   `+ Операция` → переключить сегмент на «Доход» → выбрать «Зарплата» →
   ввести `50000` → сохранить. Баланс должен вырасти.

4. **Добавить новый счёт.**
   Вкладка «Счета» → `+` → название «Карта», тип «Карта», начальный
   баланс `10000` → «Сохранить». Он появится в списке; при добавлении
   следующей операции он появится как вариант выбора.

5. **Удалить операцию.**
   Вкладка «Операции» → свайп операции влево → подтвердить удаление.
   Баланс на главной пересчитается автоматически.

6. **Проверка Offline First (обязательный тест DoD).**
   Включить **режим полёта** на телефоне. Полностью закрыть и снова
   открыть приложение. Все данные должны быть на месте, добавление и
   удаление операций должно работать без ошибок и задержек.

7. **Проверка холодного старта.**
   Полностью закрыть приложение, снова открыть. Все счета/операции —
   на месте (данные лежат в локальном Isar).

Если хотите начать с нуля — «Приложения» → MyMoney → «Очистить
данные», перезапустить: снова seed'нутся системные категории и «Наличные».

### Приёмочный сценарий Этапа 2 — планирование (по § 24 Bible)

Всё также работает **офлайн**; бэкенд-часть Этапа 2 существует
параллельно и подключится к клиенту в Этапе 4.

**Бюджет** — вкладка «Бюджет».

1. Нажать `+` (правый нижний угол) → выбрать категорию расходов
   (например «Продукты»), период «Месяц», ввести план `20000` →
   «Сохранить». Появится карточка с прогресс-баром.
2. Перейти на «Операции» → добавить расход в той же категории на
   `500 ₽`. Вернуться на «Бюджет» — прогресс-бар должен вырасти,
   «Потрачено» = 500 ₽, «Осталось» уменьшилось на 500 ₽.
3. Добавить расход, превышающий план. Полоска станет красной,
   строка сменится на «Превышение на … ₽».
4. Тап по карточке — открывается лист с редактированием суммы плана
   (категорию/период менять запрещено — они образуют идентичность
   бюджета).
5. Длинный тап по карточке — удаление.

**Цели** — вкладка «Цели».

1. `+` → название «Отпуск», целевая сумма `100000`, опционально дата →
   «Сохранить».
2. На карточке — кнопка «Пополнить» → ввести `20000`. Прогресс-бар
   вырастет до 20%.
3. Кнопка «Снять» → нельзя увести в минус (клиент молча блокирует).
4. При достижении цели рядом с названием появляется галочка ✓.
5. Тап по карточке — редактирование, длинный тап — удаление.

### Приёмочный сценарий Этапа 3 — аналитика (по § 24 Bible)

Всё также работает **офлайн**. Статистика собирается исключительно из локальных данных Isar.

**Аналитика** — вкладка «Статистика» (иконка графика).

1. По умолчанию показывает отчёт за **текущий месяц**.
2. Переключение периода: нажать на сегментированный контроль — выбрать «Неделя», «Месяц» или «Год». Диаграмма перестраивается.
3. Карточки в верхней части показывают:
   - Доход за период
   - Расход за период
   - Остаток (доход − расход)
4. Круговая диаграмма (pie chart) — распределение расходов по категориям, каждый сегмент — процент от всех трат за период.
5. Таблица ниже диаграммы — расходы по категориям в руб. и %, отсортированы по убыванию суммы.
6. Если есть бюджеты на период — таблица «Сравнение с бюджетом» показывает:
   - План на категорию
   - Потрачено в действительности
   - Статус («В норме» / «Превышено»)
   - Прогресс-бар (зелёный если в норме, красный если превышено)
7. Кнопка «Экспортировать PDF» → генерирует отчёт и предлагает поделиться (Email, Google Drive, облако и т.д.).

**Проверка:**
1. Добавить несколько операций разных категорий в «Операции».
2. Перейти на вкладку «Статистика» — диаграмма должна показать все категории.
3. Переключить период «Неделя/Месяц/Год» — каждый раз пересчитывается только то, что попало в окно.
4. Экспортировать PDF → проверить, что файл содержит верные суммы, названия категорий, дату отчёта.

## 6. Что НЕ работает на Этапе 3

Реализовано в бэкенде и есть в схеме, но UI на мобильном пока нет:

- Регистрация / логин / синхронизация — придёт в Этапе 4.
- Переводы между счетами (тип TRANSFER) — API готов, но экран «Новая
  операция» на мобильном сейчас только для доход/расход.
- Редактирование операции (обновление с audit trail в
  `transaction_history`) — API готов, UI-экран будет добавлен по
  ходу полировки.
- Долги, подписки — Этап 5.
- Тренды, прогнозирование, расширенная аналитика — Этап 3+ (пост-MVP).

## 7. Возможные проблемы и решения

| Симптом | Решение |
|---|---|
| `docker compose` ругается на порт `5432` | Локальный Postgres уже занят порт — остановить его или изменить `POSTGRES_PORT` в `.env` |
| Первый `./gradlew run` очень долгий | Нормально, скачиваются Kotlin/Ktor/Exposed |
| Backend не стартует, ругается на JDBC | Проверить, что Postgres запущен (`docker compose ps`) и `DB_URL` в `.env` корректен |
| Flutter: «Target of URI not found: '…entity.g.dart'» | Не запущен build_runner — выполнить `dart run build_runner build --delete-conflicting-outputs` |
| `flutter devices` не видит телефон | USB-режим «Передача файлов» + переустановить Google USB Driver через Android Studio |
| Приложение падает при первом запуске | Проверить, что в pubspec есть `isar_flutter_libs` и что дал разрешение на запись хранилища |
| На главной пусто, но кнопка «+ Операция» не работает | Проверить, что seed прошёл: удалить данные приложения через Настройки → Приложения → MyMoney и перезапустить |

## 9. Ручная приёмка Этапа 4 (семья + синхронизация)

Требует запущенного бэкенда (см. §2). Мобильное приложение по умолчанию
обращается к `http://10.0.2.2:8080` — это адрес хостовой машины из
Android-эмулятора. На реальном телефоне нужно вписать локальный IP ПК:
`http://192.168.x.y:8080` (телефон и ПК в одной Wi-Fi-сети).

Сценарии:

**Регистрация и первый sync.**
1. В приложении: «Настройки» → «Войти / Зарегистрироваться» → вкладка
   «Регистрация».
2. Ввести email + пароль (≥ 8 символов), нажать «Зарегистрироваться».
3. Локальный Isar очищается, стартует первый pull → на вкладке «Категории»
   появляется серверный seed.
4. Открыть «Настройки» → раздел «Синхронизация» → должна быть
   заполнена «Последняя синхронизация».

**Ручная синхронизация.**
1. Создать пару операций локально.
2. «Настройки» → «Синхронизировать сейчас» → SnackBar показывает
   `pushed=N, pulled=M, conflicts=0`.

**Приглашение в семью (двух пользователей).**
1. С устройства A (owner): «Настройки» → «Управление семьёй» → ввести
   email пользователя B → «Создать приглашение» → нажать «Скопировать».
2. С устройства B (только что зарегистрированного): «Настройки» →
   «Управление семьёй» → вставить токен в поле «Принять приглашение»
   → «Принять».
3. Приложение B выйдет из учётной записи (сервер отозвал refresh).
   Заново войти с email B — теперь `familyId` совпадает с A.
4. После sync на B должны появиться операции A. Изменения B тоже
   пропишутся в семью A после его следующего push.

**Проверка LWW-конфликтов.**
1. Устройство A изменяет операцию X → «Синхронизировать сейчас».
2. Устройство B (без предварительного pull) редактирует ту же X →
   «Синхронизировать сейчас».
3. Ожидание: B получает `conflicts=1`. Локальная версия B перезаписывается
   на серверную (версию A). Проверить, что старая версия B видна
   в истории (когда UI истории будет добавлен на дальнейших этапах).
